# depos-action E2E

Одноцелевой fixture-репозиторий для проверки полного жизненного цикла Pull Request, создаваемого [`depos-action`](https://github.com/Stivo182/depos-action).

## Первоначальная настройка

В настройках репозитория включите:

**Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests**.

Дополнительные secrets в этом репозитории не требуются.

## Запуск

Workflow `Контроллер E2E` запускается:

- вручную из вкладки Actions — для указанной ветки, тега или SHA `depos-action`;
- ежедневно — для `Stivo182/depos-action@main`;
- комментарием `/test` в Pull Request основного репозитория.

```text
/test
```

Команда доступна только администраторам основного репозитория. Workflow `.github/workflows/e2e-command.yml`, обрабатывающий комментарий, должен находиться в его ветке по умолчанию. До слияния этого workflow команда `/test` не запускает E2E.

## Выполнение тестов

При запуске по команде контроллер получает номер Pull Request и выбирает `refs/pull/<номер>/head`. При ручном запуске версия указывается параметром `ref`, а ежедневный запуск использует `main`.

Контроллер получает выбранную версию `depos-action`, определяет точный SHA и передаёт его всем исполнителям. Каждый исполнитель загружает тот же SHA в каталог `depos-action-local` и запускает Action через `uses: ./depos-action-local`.

Для каждой попытки создаются отдельные временные ветки. Набор проверяет:

- создание Pull Request;
- повторное использование существующего PR;
- поведение при отсутствии обновлений;
- автоматическое закрытие управляемого Pull Request;
- защиту посторонней пользовательской ветки.

Отдельная задача очистки выполняется независимо от результата тестов. Сначала она отменяет связанные задачи-исполнители, затем удаляет созданные тестовые Pull Request и ветки. Ошибка API, закрытия Pull Request или удаления ветки завершает очистку с ошибкой.

## Токены и безопасность

`E2E_DISPATCH_TOKEN` хранится только в основном репозитории и используется для отправки события `repository_dispatch`. Для classic PAT достаточно scope `public_repo`; fine-grained PAT должен включать оба репозитория и разрешение **Contents: Read and write**.

PAT не передаётся в E2E jobs. Тестовый репозиторий использует собственный `GITHUB_TOKEN` с разрешениями `contents: write` и `pull-requests: write`. Токен действует только внутри fixture-репозитория и не имеет доступа к `Stivo182/depos-action`.

Репозиторий предназначен только для временных тестовых данных.
